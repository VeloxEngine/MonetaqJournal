Building RESTful APIs with Supabase and Next.js

By Engineering Team • October 2026 • 9 min read • Backend Architecture

While the Next.js App Router promotes React Server Components and Server Actions for internal UI mutations, building a public or partner-facing RESTful API remains a core architectural requirement for modern web applications. Third-party integrations, mobile clients (iOS and Android), and automated webhooks all rely on deterministic HTTP semantics.

By pairing Next.js Route Handlers with Supabase's PostgreSQL engine and the @supabase/ssr authentication package, you can assemble production-grade, type-safe REST endpoints that enforce strict access control and robust payload validation.

1. Next.js Route Handlers: The App Router Standard

Route Handlers are defined in files named route.ts (or route.js) inside the app/api directory. Unlike the legacy Pages Router pages/api API routes which relied on Node.js req and res streams, modern Route Handlers use native Web standard Request and Response interfaces.

2. Production Blueprint: RESTful Resource Handler

Below is a production-ready implementation of a REST collection endpoint (/api/v1/projects) supporting both paginated GET and validated POST operations:

app/api/v1/projects/route.ts 
import { NextRequest, NextResponse } from 'next/server';
import { createServerClient } from '@supabase/ssr';
import { cookies } from 'next/headers';
import { z } from 'zod';

// 1. Strict Request Validation Schema
const createProjectSchema = z.object({
  name: z.string().min(3).max(64),
  description: z.string().max(256).optional(),
  organization_id: z.string().uuid(),
});

// 2. Helper to Initialize SSR-Safe Supabase Client
function getSupabase() {
  const cookieStore = cookies();
  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        get(name: string) {
          return cookieStore.get(name)?.value;
        },
      },
    }
  );
}

// GET /api/v1/projects (Paginated List)
export async function GET(request: NextRequest) {
  const supabase = getSupabase();
  const searchParams = request.nextUrl.searchParams;
  const limit = Math.min(Number(searchParams.get('limit')) || 20, 100);
  const offset = Number(searchParams.get('offset')) || 0;

  // Verify User Session
  const { data: { user }, error: authError } = await supabase.auth.getUser();
  if (authError || !user) {
    return NextResponse.json({ error: 'Unauthorized: Valid bearer token required' }, { status: 401 });
  }

  // Fetch Rows (Subject to PostgreSQL Row Level Security)
  const { data: projects, error, count } = await supabase
    .from('projects')
    .select('*', { count: 'exact' })
    .range(offset, offset + limit - 1)
    .order('created_at', { ascending: false });

  if (error) {
    return NextResponse.json({ error: error.message }, { status: 500 });
  }

  return NextResponse.json({
    data: projects,
    pagination: {
      total: count,
      limit,
      offset,
    },
  }, { status: 200 });
}

// POST /api/v1/projects (Create New Resource)
export async function POST(request: NextRequest) {
  const supabase = getSupabase();

  // Authentication Guard
  const { data: { user }, error: authError } = await supabase.auth.getUser();
  if (authError || !user) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
  }

  // Payload Validation
  let body;
  try {
    body = await request.json();
  } catch {
    return NextResponse.json({ error: 'Malformed JSON payload' }, { status: 400 });
  }

  const parsed = createProjectSchema.safeParse(body);
  if (!parsed.success) {
    return NextResponse.json({
      error: 'Validation Error',
      details: parsed.error.issues,
    }, { status: 422 });
  }

  // Insert into Database
  const { data: newProject, error: dbError } = await supabase
    .from('projects')
    .insert([
      {
        name: parsed.data.name,
        description: parsed.data.description,
        organization_id: parsed.data.organization_id,
        owner_id: user.id,
      },
    ])
    .select()
    .single();

  if (dbError) {
    return NextResponse.json({ error: dbError.message }, { status: 400 });
  }

  return NextResponse.json({ data: newProject }, { status: 201 });
}

3. REST Semantics & HTTP Status Code Discipline

High-quality APIs are predictable. Ensure your Route Handlers return precise RFC-compliant HTTP status codes:

Status Code Standard Meaning When to Use in Next.js + Supabase
200 OK Successful read or update Returning GET query data or PATCH updates
201 Created Resource created successfully Returning newly inserted rows on POST
400 Bad Request Malformed client payload JSON syntax parsing errors
401 Unauthorized Missing or invalid credentials Missing or expired Supabase JWT session
403 Forbidden Authenticated but lacks permissions User authenticated, but RLS denied action
422 Unprocessable Entity Validation schema failed Zod validation errors on fields

4. Rate Limiting with Upstash Redis at the Edge

Exposing unthrottled API routes invites distributed denial-of-service (DDoS) and credential stuffing attacks. Wrap critical endpoints using sliding-window rate limiters:

lib/ratelimit.ts 
import { Ratelimit } from '@upstash/ratelimit';
import { Redis } from '@upstash/redis';

export const ratelimiter = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(50, '10 s'), // 50 requests per 10 seconds
  analytics: true,
});
Architectural Note: RLS Double-Defense

Even if an attacker bypasses application-level routing logic or exploits an unchecked query parameter, PostgreSQL Row Level Security (RLS) ensures that the database itself refuses to return unauthorized rows. Always maintain security at both the application gateway and the database engine.

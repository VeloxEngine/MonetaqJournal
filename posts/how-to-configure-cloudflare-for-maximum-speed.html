How to Configure Cloudflare for Maximum Website Speed

By Engineering Team • October 2026 • 8 min read • Infrastructure Performance

Cloudflare sits in front of millions of web properties as a reverse proxy, filtering malicious traffic and terminating TLS connections across its globally distributed Anycast network spanning 310+ cities. However, many developers leave their Cloudflare dashboard on default settings, capturing only a fraction of its potential throughput. By systematically tuning HTTP/3 transport protocols, Tiered Cache hierarchies, Early Hints, and fine-grained Cache Rules, you can reduce origin load by over 85% and drive Time to First Byte (TTFB) down to single-digit milliseconds.

1. Network Protocol Modernization: HTTP/3 and 0-RTT

The foundation of web latency starts with the transport handshake. Traditional TCP + TLS 1.3 requires two roundtrips before payload transmission begins. On mobile networks with 100ms packet round-trip times, that introduces an automatic 200ms penalty.

  • Enable HTTP/3 (with QUIC): Under Speed → Optimization → Protocol, turn on HTTP/3. QUIC operates over UDP, eliminating head-of-line blocking when packet loss occurs on unstable cellular networks.
  • Enable 0-RTT Connection Resumption: This enables returning visitors to send their initial GET request alongside their TLS resumption ticket, eliminating the initial negotiation handshake completely.

2. Next-Gen Compression: Brotli and Minification

Gzip has been superseded by Brotli, which achieves 14% to 26% higher compression ratios on modern text payloads (HTML, CSS, JSON, and JS bundles). Ensure Brotli compression is strictly enforced in Cloudflare settings. Note that while Cloudflare provides auto-minification, modern frontend frameworks (Vite, Next.js, esbuild) already minify assets at compile time. Enabling origin-side source maps with pre-minified builds is generally cleaner than letting proxy layers re-parse your JavaScript syntax.

3. Turbocharging Critical Rendering with 103 Early Hints

The 103 Early Hints HTTP status code is one of the most impactful performance innovations in modern web standards. While your origin server is still busy executing SQL queries or assembling server-rendered templates, Cloudflare can immediately emit a 103 response containing Link: <...>; rel=preload headers to the browser.

HTTP/1.1 103 Early Hints Example 
HTTP/1.1 103 Early Hints
Link: </css/style.css>; rel=preload; as=style
Link: </fonts/inter-var.woff2>; rel=preload; as=font; crossorigin
Link: </js/main.js>; rel=modulepreload

The browser begins downloading your heavy CSS stylesheets and typography assets concurrently while the origin is still computing the final HTML payload, cutting Largest Contentful Paint (LCP) by up to 350ms.

4. Maximizing Edge Cache Hit Ratio with Cache Rules

The older "Page Rules" feature has been superseded by Cloudflare's modern Cache Rules engine. Instead of passing every static request back to your cloud compute instance, configure edge caching rules with explicit TTL overrides:

Path Pattern Edge Cache TTL Browser TTL Purge Strategy
/assets/*, /_next/static/* 1 Year (31536000s) 1 Year (immutable) Content-hashed URL
/blog/*, /docs/* 7 Days (604800s) 10 Minutes Webhook Purge on Publish
/api/dynamic/* Bypass Cache No-Store N/A

5. Tiered Cache and Argo Smart Routing

In a standard CDN model, if a user in Tokyo requests a resource that was previously cached only in Frankfurt, the Tokyo point of presence (POP) fetches the file directly from your origin in Europe.

Tiered Cache solves this by establishing regional tier data centers (e.g., London, Chicago, Singapore). The Tokyo POP queries the regional Singapore tier first. If the file is present in Singapore, it avoids trans-oceanic transit to your origin server entirely. Enabling Tiered Cache is completely free on Cloudflare and delivers an immediate boost to your global cache hit ratio.

Architecture Tip: Beware Rocket Loader with Modern SPAs

Cloudflare's legacy "Rocket Loader" alters script injection order to defer JavaScript execution. While effective on older jQuery sites, it can break hydration sequences in React, Vue, and Next.js applications. Keep Rocket Loader disabled when deploying modern component frameworks.

6. Summary Performance Checklist

  1. SSL/TLS mode set to Full (Strict) with TLS 1.3 enforced.
  2. HTTP/3 (QUIC) and 0-RTT Connection Resumption enabled.
  3. 103 Early Hints turned on.
  4. Brotli enabled; verify content-encoding: br in response headers.
  5. Tiered Cache topology enabled.
  6. Cache Rules created for immutable static assets (1-year TTL).
  7. Rocket Loader disabled for React/Next.js hydration safety.
